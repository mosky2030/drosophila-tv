一、一页速览

本文说明 Android TV 桌面（app.orchard.tv，Drosophila）上那只数字果蝇的全部机制：它怎么跑起来、有哪几种姿势、怎么长大、什么时候变成两只三只、怎么开怎么关，以及想改哪一条该动哪个文件。文中所有数字都取自当前代码，实测数据来自 2026-11-19 的模拟器验证。

一句话概括：它是一只活在桌面图标上层的像素果蝇，把「出生时间」当作唯一的历史，体型、只数、年龄提示全部由这个时间推导出来。

二、运行：一帧是怎么过的

2.1 它挂在哪里

果蝇是 HomeScreen 最上层的一个全屏 Canvas（HomeScreen.kt 里 PetOverlay(Modifier.fillMaxSize())），画在图标和壁纸之上。它只画、不接收按键，所以遥控器焦点永远在图标上，果蝇不会抢焦点。

2.2 心跳

PetOverlay 里有一个协程，每 33 毫秒推进一次，时间步长固定为 33 毫秒：

  • 不读取真实经过的时间。机器卡一下，果蝇是「慢动作」，而不是「瞬移」——这一点是刻意的，移动端帧间隔抖动很大，用固定步长行为才稳定。
  • 每一帧会重新读一次「桌宠开关」和「出生时间」。设置面板里一改，下一帧就生效，不需要重启桌面。

2.3 一次心跳做四件事

  1. 算年龄：now - 出生时间，出生时间为 0 时按 0 岁处理（绝不当成 1970 年）。
  2. 算该有几只：1 只、2 只还是 3 只（见第五节）。
  3. 对齐名册：不够就补一只，多了就减一只。
  4. 逐只推进状态机，并把体型写进各自的状态里。

2.4 画面帧怎么选

所有动画都由「第几帧」这个计数器推出来，不引第二套时钟：仰面用第 14 帧；飞行时第 3、13 帧交替（15 Hz 扇翅）；爬行按步态相位取第 3–10 帧；呆着时第 1、0、1、2 帧轮流（每 13 帧换一档，就是头部左右慢慢摆）；此外每 8 秒（242 帧）有一次极快的收翅动作，第 3→11→12→13→12→11 帧在 8 帧内走完。

2.5 缩放与取样

画的时候把 64 px 的精灵图缩放到当前体型。规则是：

  • 体型大于 64 px（放大）用最近邻取样，像素格子变粗、边缘不糊；
  • 体型小于 64 px（缩小）用双线性取样，避免抽点把细腿抽断。

这是 2026-11-18 踩过的坑：早期版本对放大也做插值，翅膀左右落在不同像素网格上，越折越歪。

三、姿势与行为：五个状态

3.1 状态一览

3.2 状态怎么流转

「呆着」是枢纽。每次呆够时间后掷一次骰子：30% 起飞，70% 开始爬。爬完、飞完都回到「呆着」。唯一的例外是飞行撞到桌面边缘，会翻成「仰面」，躺一会儿转成「自转」，转完硬切回「呆着」。

设计意图（用户 2026-11-19 定的调子）：大部分时间应该是爬着、走动、飞行这些基本动作；撞墙仰面自转是极小概率的意外，不该经常出现。

3.3 步态：按距离推进，不按帧

走路的八帧由「步态相位」gait 驱动，相位每帧按当前速度增加：gait += 0.033 × (0.8 + 速度 × 0.006)，取值 0 到 1，乘 8 就是当前该用第几帧。

早期版本是「每帧换一帧」，等于固定每秒 3.75 步。爬速从 320 降到 200 之后，那套算法就变成了「原地狂奔」：脚动得飞快、身体几乎不动。改成按距离推进之后，步子跟着地面速度走，慢走就是慢步子。

3.4 为什么撞墙翻面这么少

正常飞行在起飞时会先做两件事：

  1. 看前方还有多远：沿当前朝向算到飞行边界的距离，如果不足 320 px，就掉头朝屏幕中心飞；
  2. 把距离收进桌面：用和飞行完全相同的积分式（朝向按正弦摆）把整条弯曲航迹预演一遍，一碰到边界就在那里截断，下限 120 px。

只有 3% 的飞行是「直冲边缘」，也就是刻意的撞墙，才会真的翻面。改之前不做预演，实测 46% 的飞行以撞墙结束，翻面从意外变成了常态。

4.3 为什么指数是 0.35

这个指数要同时满足三件事，试出来的：

  • 头一天得看得出长了一点。18 到 38 px，一夜之间身子大了一圈，养着才有反馈；
  • 一个月不能把增长用光。30 天 86 px，还剩三分之二的路可以走；
  • 一年收口。线性曲线前几周几乎看不出来（每天零点几像素，比屏幕像素还细），平方根曲线又会在头十天把大半增长吃掉。

4.4 上限为什么是 180 px

上限等于最小值的 10 倍，是用户 2026-11-19 明确要求的（原话是「最大的时候是最小的时候的 10 倍，现在感觉是大概 4-5 倍」）。

历史背景：上一版权重上限是精灵图的原生尺寸 64 px，那样最大只有最小的 3.6 倍，在电视上仍然像个「小虫子」。代价是 180 px 相当于把 64 px 的图放大 2.8 倍，像素格子会变粗——而这正是像素风该有的样子，所以放大时改用最近邻取样，只放大不糊。

最小值 18 px 也不是随手定的：试过 14 px 和 11 px，在 1080p 电视上只剩一团色块，认不出是苍蝇。

五、族群：半年两只，一年三只

5.1 规则

主果蝇年龄场上只数构成
不足 180 天1 只主果蝇
满 180 天2 只一大一小
满 365 天3 只两大一小
之后3 只（封顶）不再增加

5.2 每只的体型怎么来

第二只、第三只有自己的出生时间，这个时间是从主果蝇算出来的：第二只「出生」在主果蝇满 180 天的那一刻，第三只「出生」在满 365 天那一刻。之后每只按自己的年龄走同一条成长曲线。

这样一来，刚满半年那天冒出来的第二只就是最小的 18 px，一岁时第二只已经 185 天大（约 146 px）、第三只刚出生（18 px），正好是用户要的「两大一小」。

5.4 为什么不给成员单独存档

因为「更新之后变回一只」是最难查的一类故障。现在只存一个出生时间，只数完全由年龄推导，所以只要主果蝇的历史还在，族群数量就一定是对的——重装、升级、换机型都不会把三只变回一只。

5.5 想让新成员永远小一号怎么改

当前设计里新成员自己也会长大，养久了三只一样大（730 天那一行）。如果希望「小的永远小」，把 PetGrowth.pxOf 里第二、第三只的年龄换成一个固定值即可，例如：

fun pxOf(index: Int, ageSec: Float, preview: Int): Float =
    if (index == 0) px(ageSec, preview) else px(30 * 86_400f, preview)

这样新成员会固定在「养了一个月」的 86 px，不再继续长大。

5.6 三只互不重叠

每只都有按自己体型算出的半径（体型的 0.55 倍）。每一轮状态推进结束后，检查所有成员两两之间的距离；一旦小于两半径之和再加 10 px，就把两只对称推开，推完再夹回屏幕边界内。两只满体型（180 px）时中心至少要隔开 208 px。

放在状态推进之后做，是为了让「两只正朝对方爬」看起来像擦肩而过，而不是穿过去叠成一只。仰面自转是绕各自的 spinX/spinY 画小圈，推开一个成员的时候圆心也要跟着搬同样的距离，否则下一帧它就被拉回原处、又重叠了。

六、打开与关闭

6.1 开关在哪里

设置面板 → 个性化 → 桌宠，两档：关闭 / 像素果蝇。入口在首页按菜单键呼出的控制中心里。

6.2 关闭会发生什么

选「关闭」不会立刻生效，会先弹一个确认框，框里报两件事：这只果蝇已经养了多久（分钟 / 小时 / 天），以及一共长出了多少像素。选择「继续养着」或返回，什么都不变；选择「确认关闭」，两处出生时间一起清掉，下一次打开时从 18 px 重新养起。

先问一次是有理由的：关一下就丢掉一年的成长，不该一个按键就完成。

6.3 历史是怎么保住的

出生时间是这只果蝇的全部历史，所以存了两份：

  1. 设置里的 pet_born_at；
  2. 应用私有目录里的 files/pet_birth（纯文本，一个毫秒时间戳）。

启动时两份都读，取更早的那一个（多算几天好过丢掉一年）；只要有一份缺失或者两份不一致，立刻把正确值补写回两份。老版本升级上来的用户第一次启动就会把第二份建好。

两种都空的极端情况下（从还没有这个字段的版本升级、或者数据被外力清过），如果桌宠是开着，就直接把「现在」写成出生时间。这一条是必须的：出生时间为 0 时如果照字面算年龄，会被算成「从 1970 年养到现在」，一上来就是满体型，然后在设置面板里随手动一下又缩回最小——看起来就像历史被偷走了。

6.4 会丢历史的三种操作

  1. 在面板里确认关闭桌宠；
  2. 清除应用数据（pm clear），两份副本会一起消失；
  3. 卸载重装（不是覆盖安装）。

前两种是明确意图或者明确的破坏，第三种属于系统行为。除此之外，覆盖安装新版本不会动这两份数据。

7.2 设置面板里的调试行

只有调试版（BuildConfig.DEBUG）有「体型（调试）」这一行，可选按年龄 / 最小 / 最大，用来当场看两个极端，不必等一年。这一档不落盘，重启就回到按年龄，免得哪天忘了自己开过、以为真的养到头了。正式包里这一行根本不存在。

7.3 在模拟器上把年龄改成任意天

模拟器的调试版可以直接改数据。顺序很重要：先写盘，再 force-stop——这个应用本身就是桌面，force-stop 之后系统会自己把它拉起来，反过来做就会让它抢在写盘之前读到旧值。

# 先写两份出生时间（单位毫秒），再让它自己重启
adb -s emulator-5554 push settings_new.xml /data/local/tmp/s.xml
adb -s emulator-5554 shell run-as app.orchard.tv cp /data/local/tmp/s.xml shared_prefs/settings.xml
adb -s emulator-5554 shell run-as app.orchard.tv cp /data/local/tmp/pb files/pet_birth
adb -s emulator-5554 shell am force-stop app.orchard.tv

仓库里的 docs/_pettest/set_age.sh 400 把这一套包好了，参数是天数。

7.4 看启动时读到的出生时间

每次启动会往 logcat 里写一行，两份副本和实际采用值都列出来：

九、踩过的坑

  1. 四根触角。头部图层本身已经含了两根触角，合成时又把镜像的一半画了一次，于是四根。现在头与腹各合成一次。
  2. 最小体型 11 px、14 px 认不出。1080p 电视上只剩一团色块，最终定在 18 px。
  3. 46% 的飞行以撞墙结束。飞行距离拉长之后必然撞墙，翻面成了常态。改成起飞前预演整条航迹、并把距离截在边界前。
  4. 走路像原地狂奔。步态按帧推进导致步频固定，爬速降下来之后不匹配。改成按地面速度推进。
  5. 时间全花在发呆上。原本爬完呆 1–30 秒、飞完呆 2–18 秒，实测 65% 的时间在发呆。一度缩到 0.6–2.6 秒 / 0.8–3 秒，发呆降到 56%；the owner 2026-11-19 先改到 0.6–30 秒（实测呆着 90%、爬 8%、飞 1%，几乎一直站着），随后把上限收到 8 秒；现在呆着 74%、爬 21%、飞 2.7%，基本动作重新占回大半。
  6. 放大插值把翅膀弄歪。翅膀左右落在不同像素网格上，越折越歪。改成放大用最近邻。
  7. 出生时间为 0 被当成 1970 年。表现为「一上来就是满体型，一碰设置又缩回最小」。现在两份都空时直接种下「现在」。
  8. 升级与备份。出生时间从只有一份到两份，中间有一版判断写漏了「副本存在但值为 0」的情况，导致升级用户永远建不出副本。现在的判据是「只要和任一份不一致就补写」。
